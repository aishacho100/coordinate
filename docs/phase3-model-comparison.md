# Phase 3 モデル比較(実測)

実施日: 2026-10-17 / 評価スクリプト: `npm run eval -w api`(`apps/api/scripts/eval.ts`)
対象: Unsplash の写真 10 枚(全身・上半身・夜景・ブランド文字入り・靴の寄り)。写真は Git 管理外(`apps/api/eval/photos/`)。
モデルの呼び出しは構造化出力(`output_config.format`)、思考の深さは `medium`。

## 結果の要約

| | Sonnet 5.5 | Haiku 5.5 | Opus 5.5 |
|---|---|---|---|
| 評価した写真 | 10 枚 | 10 枚 | 5 枚(最初の 5 枚のみ) |
| リクエストの失敗 | 0 | 0 | 0 |
| 平均の出力トークン | 約 530 | 約 1,180 | 約 670 |
| 平均の所要時間 | 約 4.3 秒 | 約 6.5 秒 | 約 8.7 秒 |
| 1 写真あたりの概算費用(※) | 約 $0.013(約 2 円) | 約 $0.001(約 0.15 円) | 約 $0.029(約 4.4 円) |

入力は写真 1 枚あたり約 3,960 トークンで、モデルによらず同じ。
※ 料金は 2026-10-06 時点の公開価格の写しで概算(Sonnet $2/$10、Haiku $0.10/$0.50、Opus $4/$20 per 100 万トークン、円は 1 ドル 150 円で換算)。実際の請求は最新の料金表で確認すること。`apps/api/.env` の `PRICE_*` を設定すると、評価と API ログに概算が出る。

## 検出の精度(写真と目視で照合)

- 服・靴・バッグ・腕時計・帽子は、3 モデルとも枠がおおむね正しい位置に付いた。
- 全身が写っているか(`fullBody`)は、25 件すべて正しかった。
- **ブランド**: 文字が読める 4 枚(Nike のパーカー、adidas のジャケット、adidas のスニーカー、Nike Air のタグ)で、Sonnet と Haiku は同じブランドを、読み取った文字を根拠にして採用した。ロゴだけ(文字なし)の黒パーカーは、2 モデルとも採用しなかった(設計どおり)。標語入りの T シャツも、ブランドにはしなかった。**推測によるブランドの誤採用は、全モデル・全写真でゼロ。**
- モデルごとの癖:
  - Sonnet: 最も安定。透明なレンズの眼鏡を「サングラス」と判定した例がある。
  - Haiku: 両足の靴を 1 つの大きな枠にまとめた例がある。出力トークンが多く、Sonnet より遅い。
  - Opus: 人が大勢いる写真で「その他の靴/バッグ/衣類」のような粗いカテゴリを選び、ジーンズを見落とした。Sonnet より遅く高い。
- 複数人が写る写真(渋谷の通り)では、手前の 2 人の持ち物が 1 つの一覧に混ざる。アプリは 1 人を想定しているため、結果画面での削除・修正が前提になる。

## 写真品質の評価(しきい値)

- 低解像度(短辺 720px 未満): 幅 600px のサムネイル 8 枚すべてを検出。
- 暗さ(平均輝度 60 未満): 輝度を落とした写真と、夜の写真で検出。
- ぼけ: 実装に不具合があった(`sharp` の `stats()` は処理前の入力を測る)ため修正。鮮明な写真のラプラシアン標準偏差は 12.7〜51、強いぼかし(σ16)は 2〜5。しきい値 8 で、鮮明な写真を誤判定せず、強いぼけを検出できる。背景のぼけた写真(最小 12.7)は余裕を取って通す。

## 未確認

- 複数ブランドが同じ写真に写るケース、筆記体や小さな文字のロゴの読み取り。
- 日本語の文字だけのブランド表記(`ユニクロ` と `UNIQLO` の対応づけはしない設計)。
- 10 枚は少ない。モデル間の差の小ささは、この枚数での観察にとどまる。
