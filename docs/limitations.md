## Phase 2 で確認できていないこと

- **iOS**: 開発環境が Windows のため、iOS では一切動作確認していない。
- **Expo Go での「端末に保存」**: `expo-media-library`(SDK 57)のネイティブ部分が Expo Go に含まれないため、保存は利用できない。この場合は共有から保存するよう案内する。開発ビルドでの確認結果は README / 作業報告を参照。
- **実写真での見た目**: 動作確認は合成した単色のテスト画像のみ。実際のコーデ写真での文字の読みやすさは未検証。
- **複数端末・画面サイズ**: Pixel 7 エミュレータ(API 35)1台のみ。

## Phase 3(AI アイテム検出)の制約

- **ブランドは写真に写った文字からしか読み取らない**。文字が写っていない、または読めない場合は「ブランド不明」と表示する。
- **ロゴの形だけではブランドを採用しない**(例: 文字のないスウッシュだけの黒パーカーは不明のまま)。標語や柄の文字もブランドとして扱わない。誤ったブランドを出さないことを優先した設計で、そのぶん不明が増える。
- **複数人が写る写真では、全員の持ち物が 1 つの一覧に混ざる**。アプリは 1 人を想定しており、結果画面での削除・修正が前提。
- 写っていない部分のアイテムは検出されない(上半身だけの写真では靴やパンツが出ない)。結果画面の「アイテムを追加」で手動で足す。
- 手動で追加したアイテムには位置情報がないため、編集画面のラベルは写真の中央付近に置かれる。
- 枠の位置・カテゴリはモデルの判定で、透明なレンズの眼鏡を「サングラス」とするなどの誤りがある(`docs/phase3-model-comparison.md`)。
- 解析には写真をサーバー(`apps/api`)経由で Anthropic の API へ送る。サーバーは現在ローカルでのみ動作し、デプロイしていない。
- 認識結果画面で戻る操作(Android の戻るキー・iOS のスワイプ・ヘッダーの戻る)をすると、編集内容が失われる問題は解消済み(編集または検索結果があるときは確認ダイアログを出す)。
- 未確認: 複数ブランドが同じ写真に写るケース、筆記体や小さな文字のロゴ、日本語表記だけのブランド(`ユニクロ` と `UNIQLO` の対応づけはしない設計)、iOS・実機での解析。

## Phase 4(商品特定)の既知の制約

- **利用回数の上限は IPv6 を /64 に丸めていない**。IPv6 では同じ利用者がアドレスを変えて IP ごとの上限を回避できる(認証ではなく、費用の暴走を抑える目安の仕組み)。
- **同時に処理する識別の数に上限がない**。短時間に多数のリクエストが来ると、Claude・検索の費用や負荷が一時的に増える(1 日の上限と月間上限は効く)。
- **外部サイトの商品名は検索結果のまま Claude に渡す**。商品名に紛れた指示文(プロンプトインジェクション)への対策は未実施で、照合結果が誤る可能性がある(A は読み取り文字・画像・名前の一致が必要なため、単独では確定しにくい設計)。

## 設計上の制約

- トリミングの位置を変えると、ラベルは写真ではなくキャンバスに対する相対位置で保持されているため、写真に対してずれる。ラベルを置く前にトリミングを決める想定(画面にも案内を表示)。
- 90°回転はラベル位置も一緒に回すが、ラベルの文字は回らない。
- 写真は取り込み時に長辺 3000px へ縮小し、JPEG(品質 0.92)で再エンコードする。EXIF(位置情報を含む)はこの時点で除去される。
- 書き出しは幅 1080px 固定。より高解像度の出力は未対応。
- 「元に戻す」の履歴は最大 100 件。アプリを終了すると編集内容は失われる(下書き保存は未実装)。
- パッケージ ID(`com.example.coordinate`)は仮の値。リリース前に変更が必要。
