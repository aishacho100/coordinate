# Phase 3 設計: AI アイテム検出と認識結果画面

日付: 2026-10-15 / 状態: 設計承認済み(実装前)

## 目的と範囲

コーデ写真 1 枚から着用アイテムを検出し、ユーザーが認識結果画面で確認・修正して編集画面へ進めるようにする。

**含む**: `apps/api`(Fastify)、写真品質評価、Claude Vision による検出、テスト用ローカルカタログ、`analyzing` / `result` 画面、編集画面へのラベル受け渡し、実測とモデル比較の記録。

**含まない**: 実カタログ(楽天 API 等)、価格取得、ユーザー訂正の記録と評価(Phase 5)、本格的なレート制限・SSRF 対策(Phase 6)、デプロイ。

## 決定事項

- 写真品質評価はサーバー側(sharp で解像度・明るさ・ぶれ。全身が写っているかは検出結果から判定)。
- モデルは `ANTHROPIC_MODEL` で切り替え。初期値は Sonnet 5.5。実装後に Sonnet / Haiku / Opus を手元のコーデ写真で比較し、精度・コスト・速度を記録してから既定値を確定する。
- ブランドは、ロゴや文字が写真から読み取れた場合のみ出す。推測では出さず、読み取れなければ `unidentified`。
- サーバーは画像を保存しない(メモリ上で処理して破棄、ログにも残さない)。
- API キーは `apps/api/.env`(Git 管理外)のみ。アプリには入れない。
- ダミー商品を実在商品として表示しない。モックの成功を AI 解析の成功として報告しない。

## 構成

```
mobile ──POST /v1/analyze (multipart: 画像1枚)──▶ api
                                                  ├ 画像検証(JPEG/PNG、10MB 上限)
                                                  ├ 品質評価(sharp)
                                                  ├ Detector(ClaudeVisionDetector)
                                                  └ CatalogProvider(ローカル・「テスト用」表示)
mobile ◀── JSON ─────────────────────────────────┘
```

画像はアプリ側の既存取り込み(長辺 3000px、EXIF 除去)を通して送る。サーバーは Claude へ渡す前に長辺 1568px 程度へ縮小する。

### `packages/shared` に追加

- `Detector`: `detect(image) → DetectedItem[]`。
- `DetectedItem`: カテゴリ id(`DEFAULT_CATEGORIES`)、正規化座標 `Box`、色、読み取れたブランド文字列とその根拠、`Confidence`、`IdentificationLevel`。
- `CatalogProvider`: `search(query) → Product[]`。実装はローカルのテスト用(`source: 'test'`、画面でも「テスト用」と表示)。
- `Embedder` / `Reranker`: インターフェースのみ。実装は後続フェーズ。
- レスポンスの zod スキーマ(アプリとサーバーで共有)。

## API

`POST /v1/analyze` のレスポンス:

```
{
  quality: { ok, issues: ('low_resolution'|'too_dark'|'blurry'|'not_full_body')[] },
  items: DetectedItem[],           // 空もありうる
  model: string,                   // 実際に使ったモデル名
  timings: { quality, detect, total }  // ms
}
```

- 品質が悪くても検出は試みる。`issues` は結果画面で助言として表示する。
- Claude にはツール呼び出し(JSON スキーマ指定)で構造化出力を返させ、zod で検証する。不正なカテゴリ id・範囲外の座標は破棄し、成功として数えない。
- 画像検証(形式・サイズ)は他の処理より前に行う。IP 単位の簡易レート制限の入口を置く(本格対応は Phase 6)。

### エラー

| 状況 | API | アプリの表示 |
|---|---|---|
| 画像が不正・大きすぎ | 400 | 理由を表示し、写真の選び直しへ |
| Claude の失敗・タイムアウト | 502 | 「解析に失敗しました」+ 再試行 |
| キー未設定 | 503 | 「解析サーバーが未設定です」(開発者向け文言は出さない) |
| 検出 0 件 | 200 | 「アイテムを見つけられませんでした」+ 手動でラベル追加 |

## アプリの画面フロー

1. 写真を選ぶ → `analyzing`。段階表示(品質確認 → 検出 → 切り抜き → 特徴抽出)は、返ってきた `timings` に基づく完了表示とし、偽の進捗バーにはしない。
2. `result`: 検出アイテムを写真上の枠と一覧で表示(カテゴリ・ブランド・識別レベル)。ブランド未検出は「ブランド不明」。カテゴリ変更・ブランド手入力・削除・手動追加ができる。
3. 確定すると、検出結果を編集画面のラベルとして配置(初期位置は `Box` から算出)して `editor` へ進む。

## テスト

- `packages/shared`: 新スキーマの単体テスト。
- `apps/api`: 画像検証、品質評価(合成画像)、検出結果の検証と破棄を、Claude をモックしてテスト。実 Claude を呼ぶ評価は `npm run eval` として分離し、キーがなければスキップする。
- `apps/mobile`: 修正操作(変更・削除・追加)と、検出結果→ラベル変換を reducer / 純関数でテスト。
- 報告方針: モックでの成功を「AI 解析が動いた」とは報告しない。エミュレータで実際の Claude を呼んだ結果は別に記録する。

## 実装順序

1. `packages/shared` に型とスキーマ
2. `apps/api` の土台(Fastify、環境変数、画像検証、ヘルスチェック)
3. 品質評価(sharp)
4. `ClaudeVisionDetector` とモデル切替
5. ローカルのテスト用カタログ
6. アプリ側の API クライアントと `analyzing` 画面
7. `result` 画面と編集画面への受け渡し
8. 実測とモデル比較の記録
